# Live Chat Integration — FluxyChat + Cohere

> Referenced by CLAUDE.md via `@agent_docs/live-chat.md`. Implements Phase 8.
> **Pipeline integration:** The chat AI agent is pipeline-aware — it can query the pipeline state to answer "where is my build?" questions.

## Overview

Customer service is powered by FluxyChat — an open-source (MIT) realtime chat platform that runs natively on Cloudflare Workers + D1 + Durable Objects. It integrates directly into the Bicameral stack with zero additional infrastructure. AI responses are generated by Cohere via FluxyChat's custom LLM provider support. The flow is AI-first with human escalation — the AI handles common questions automatically and escalates complex issues to human agents via FluxyChat's built-in HITL (Human-in-the-Loop) system.

## Pipeline-Aware Support

The FluxyChat AI agent is aware of the 4-agent pipeline. When a founder asks about their build, the agent queries the `pipeline_runs` table and can report:

- **Which step the pipeline is on** (1=Architect, 2=Researcher, 3=Designer, 4=Coder)
- **Progress within a step** (e.g., "The Research agent is 3 of 5 sources into its analysis")
- **Blueprint approval status** ("Your blueprint is awaiting review — please check the Design tab")
- **Coder iteration count** ("The Code agent is on iteration 3 of 5 — fixing a TypeScript error")
- **Error details** if the pipeline failed ("Step 4 failed after 5 iterations — the error was about a missing React import")
- **Estimated time remaining** based on historical per-step P95 times

### Pipeline Query Implementation

```typescript
// The FluxyChat AI agent can query pipeline state via a custom tool
const pipelineQueryTool = {
  name: "get_pipeline_status",
  description: "Get the status of the user's active pipeline run",
  parameter_definition: {
    type: "object",
    properties: {
      user_id: { type: "string", description: "The user's ID" }
    },
    required: ["user_id"]
  }
};

// When the AI agent invokes this tool, it queries D1:
// SELECT * FROM pipeline_runs WHERE user_id = ? AND status NOT IN ('deployed', 'error', 'cancelled')
//   ORDER BY created_date DESC LIMIT 1
// Returns: { step, agent, status, iteration, estimated_time_remaining }
```

## Why FluxyChat (not Chatwoot)

| Factor | FluxyChat | Chatwoot |
|--------|-----------|----------|
| License | MIT | MIT |
| Infrastructure | Cloudflare Workers + D1 (same stack) | Ruby/Rails + PostgreSQL + Redis (separate VPS) |
| Cost | $0 (runs on existing Workers) | $24/mo VPS |
| AI integration | Built-in custom LLM provider | Webhook-based |
| Human escalation | Built-in HITL approval system | Manual queue |
| React support | `@fluxy-chat/react` hooks | Script tag widget |
| WebSocket | Native Durable Objects | ActionCable (Rails) |
| Monorepo | pnpm workspaces (same as Bicameral) | Ruby bundler |
| Database | D1 (same as Bicameral) | PostgreSQL (separate) |
| Pipeline awareness | Native (queries D1 pipeline_runs) | Would need custom integration |

## Integration Plan

### Step 1: Add FluxyChat as monorepo dependency
FluxyChat uses pnpm workspaces (same as Bicameral). Two integration options:

**Option A — npm packages (recommended):**
```bash
pnpm --filter @bicameral/web add @fluxy-chat/sdk @fluxy-chat/react
```

**Option B — Monorepo include (if deeper customization needed):**
Clone FluxyChat into `packages/fluxychat/` and wire as a workspace dependency.

### Step 2: Configure FluxyChat Worker
FluxyChat runs as a Cloudflare Worker. Add it as a separate Worker in the monorepo:

```
apps/
├── web/           # Bicameral main app
└── chat/          # FluxyChat worker (or merge into web/)
```

Or merge FluxyChat routes into the existing Bicameral Worker by mounting FluxyChat's Hono routes under `/api/chat/*`.

### Step 3: Configure AI Agent with Cohere + Pipeline Awareness
```typescript
// Create a FluxyChat AI agent pointing to Cohere
const agent = await fluxyClient.createAgent({
  name: "Bicameral Support Assistant",
  handle: "support-ai",
  provider: "custom",
  llmBaseUrl: "https://api.cohere.com/v2",  // Cohere API
  model: "command-r7b-12-2024",               // Free tier for cost efficiency
  capabilities: ["chat"],
  systemPrompt: `You are Bicameral's customer support assistant.
    Be helpful, concise, and friendly.
    
    You have access to the Bicameral pipeline system. When users ask about
    their build status, use the get_pipeline_status tool to check their
    active pipeline runs. The pipeline has 4 steps:
    1. Architect (Prompt Companion) — turns vision into project brief
    2. Researcher (Research Discovered) — validates tech stack
    3. Designer (Design Coherent) — creates system blueprint
    4. Coder (Architecture Implemented) — writes and deploys code
    
    If a pipeline is awaiting_approval, tell the user to review their blueprint.
    If a pipeline failed, summarize the error and offer to connect with a human.
    
    If you cannot help, say 'Let me connect you with a human agent.'
    Never make up information about pricing, features, or account details.`,
  tools: [
    {
      name: "get_pipeline_status",
      description: "Get the status of the user's active pipeline run",
      parameter_definition: {
        type: "object",
        properties: {
          user_id: { type: "string" }
        },
        required: ["user_id"]
      }
    }
  ],
});
```

### Step 4: AI-First with Human Escalation
FluxyChat's built-in HITL system handles escalation:

```
Customer message → FluxyChat WebSocket room
  → AI agent (Cohere R7B) processes message
  → If user asks about build status: query pipeline_runs table
  → If confidence high: auto-reply (streaming, token-by-token)
  → If confidence low OR user types "human"/"agent":
      → HITL approval triggered
      → Message routed to human agent queue
      → Human agent sees full conversation history + pipeline step history
      → Human takes over the conversation
```

## FluxyChat API Quickstart (from repo)

```bash
# Mint a JWT
curl -X POST "http://127.0.0.1:8787/auth/token" \
  -H "Content-Type: application/json" \
  -H "X-Fluxy-Api-Key: fc_your_api_key" \
  -d '{ "userId": "alice", "roles": ["admin"], "ttlSeconds": 3600 }'

# Create an AI agent with custom provider (Cohere)
curl -X POST "http://127.0.0.1:8787/agents" \
  -H "Authorization: Bearer <JWT>" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Bicameral Support",
    "handle": "support-ai",
    "provider": "custom",
    "model": "command-r7b-12-2024",
    "llmBaseUrl": "https://api.cohere.com/v2",
    "capabilities": ["chat"]
  }'

# Invoke agent in a room
curl -X POST -H "Authorization: Bearer <JWT>" \
  -H "Content-Type: application/json" \
  "http://127.0.0.1:8787/agents/<agentId>/invoke" \
  -d '{"roomId":"public-demo-room","content":"Where is my build?"}'
```
